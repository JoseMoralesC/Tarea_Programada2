# Cómo organizamos el cierre

Mantuvimos el reparto original: uno de nosotros desarrolla el lote A y el otro el lote B. Ambos participamos en las pruebas, la documentación y la revisión de la entrega. Los lotes se detallan en el [inventario](../info_bd/INVENTARIO.md).

Para el cierre acordamos revisar primero lo que impedía usar el proyecto y después comprobar las reglas de los datos y la instalación. Dejamos las evidencias existentes como suficientes.

| Paso | Qué revisamos juntos | Cuándo lo damos por terminado |
| --- | --- | --- |
| 1. Conexiones y permisos | Que cada cuenta pueda hacer lo que le corresponde | Las consultas funcionan y las operaciones prohibidas se rechazan |
| 2. Datos y autoría | Fechas, campos vacíos, cantidades, cambios y empleado responsable | Los errores encontrados están corregidos y tienen una prueba |
| 3. Instalación | Nombres de archivos, rutas, exportación y preparación del servidor | Podemos crear una copia siguiendo las instrucciones |
| 4. Funcionamiento | CRUD, relaciones, existencias, totales y acceso de clientes | Las pruebas con SQL real terminan correctamente en una copia |
| 5. Entrega | Código, exportación, originales y documentos | El paquete corresponde con lo que vamos a demostrar |

Cada cambio se revisa por su resultado. Si aparece un fallo, corregimos su causa y repetimos la comprobación afectada antes de cerrar el paso. No usamos el número de archivos ni los puntos del plan inicial como porcentaje de cumplimiento.
